## Why the verify hop for FleetQueueSelfMaintenanceRatioHigh "never terminates"

Root cause, two parts:

1. **The repair unit was misread as SUCCESS (hop=verify on a dead unit).**
   The 11:10:27Z dispatch unit exited non-zero per the packet EXIT CONTRACT (the
   worker appended its FAILED diagnosis and escalated — genuine structural
   signal). But alert-repair units run under `systemd-run --collect`, which
   unloads the unit at exit: `systemctl show` returns `LoadState=not-found` +
   default `Result=success`, and the 20-line journal contains only a `Started`
   line (no `Succeeded`/`Failed` — both summaries were suppressed during
   unload). So `unit_status()`'s journal fallback read the dead unit as
   success → classify() advanced the chain to **hop=verify** on a unit that
   actually failed.

2. **The laddered verify chain re-laddered forever.** The verify stall laddered
   (REDISPATCH-log + STOP-REASON → senior conference), and the verify-deadline
   mechanism (fleet-ops#1610) closed it detector-red. But that close **dropped**
   `verify_deadline_ts`/`ladder`/`stall_count`. When the cooldown expired the
   SAME dispatch unit re-opened, `take_ladder()` started FRESH → a new
   REDISPATCH-log + a new STOP-REASON (re-summoning the senior conference),
   every cycle, for as long as the alert fires. Live sequence: close
   13:07:38Z → re-ladder 14:22:11Z → auditor hand-parked `dead_until=+6h`.

## The mechanical guard

- The terminal close now **persists the ladder marker** (`ladder=stop-reason`,
  `stall_count`, `dispatch_unit`) on the cooldown state, so the chain's
  terminal identity survives the cooldown.
- A **re-open of the same dispatch unit re-parks** (sliding cooldown) and
  stays drained — no new STOP-REASON, no new REDISPATCH. The senior
  conference is summoned exactly once per dispatch unit.
- A **fresh trip** (a different dispatch unit — a re-fire or a machinery
  re-dispatch) **resets** the stale marker and opens a clean chain with the
  normal ladder, so the guard does not swallow genuine new dispatches.
- The alert leaving 9090 still closes green via the existing path.
