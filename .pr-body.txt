## What & why

The escalation-coverage canary and the credential-expiry canary both depend on
`gh issue list`. When gh is rate-limited or transiently failing, the canaries log
`WARN: could not list open issues ... (gh rc=N)` and return 0 — the tick stays
green and that tick's close coverage is silently lost. The 2026-08-31 blind spot:
24 WARN lines in 12h while the fleet-rule-coverage metric still printed covered/uncovered=0.

This PR is the class prevention (fleet-ops#366): a data-plane detector that
watches the two coverage canaries' gh-failure WARN streak, auto-files a deduped
`canary-gh-failure/<canary>` blind-spot ticket at >=3 WARNs/1h, observe-to-closes
it when the streak clears, and exports `fleet_canary_gh_failure_streak{canary=...}`.

The detector runs from the existing `fleet-heartbeat-tier1` block (no new organ,
no new scheduler), so it does not need a new absent() rule.

## Prevention mechanism (fleet-ops#366)

1. **Detector + auto-file** — `bin/fleet-canary-gh-failure-detector`: scans
   `journalctl --user -u fleet-heartbeat.service -u fleet-credential-expiry-canary.service`
   (and the canaries' marker files as the rotation fallback) for the WARN lines,
   counts per canary over a 1h window, files a `signal: canary-gh-failure/<canary>`
   ticket at >=3, observe-to-closes on a clean streak, exports the SLO metric.
   Includes `--dry-run` (used for live verification).
2. **Local-fallback marker** — `bin/fleet-escalation-canary` and
   `bin/fleet-credential-expiry-canary` now append one
   `"<epoch> <canary>"` line to `agent-state/canary-gh-failures/<canary>.marker`
   per gh-failure and truncate it on a clean tick, so the detector has a
   deterministic source even when the journal is rotated.
3. **Regression drill** — `tests/fleet-canary-gh-failure-detector.test.sh`:
   12 offline scenarios (WARN=0, under-threshold, 3-in-1h files+deps, two-tick
   dedupe, observe-to-close, under-threshold keeps open, marker fallback,
   marker write/clear, tier1+MANIFEST wiring, rule-enforcement matrix,
   `--dry-run`, and the default-journal `--since` quoting regression).
   Hosted from `tests/escalation-coverage-canary.test.sh` (already CI-listed) so
   the worker App does not need `.github/workflows/**` write access.
4. **Coverage matrix** — `config/rule-enforcement.json` `led-escalation-coverage`
   row names the detector + drill in mechanism/proof. (`lib/role-quality-gates.py`
   is not applicable: it audits per-role gates and never reads rule-enforcement.json;
   the "covered" ledger for rule-enforcement lives in config/rule-enforcement.json.)

## Live bug found + fixed in review

The prior implementation's default journal command lost the quotes around
`--since "1 hour ago"` inside a `${VAR:-default}` expansion, so `eval` ran
journalctl with `--since 1 hour ago` as separate broken args (rc=1, empty) and
the detector silently reported warn_count=0 from a journal that actually held 24
WARNs/12h. Escaped the quotes and added regression scenario 12.
