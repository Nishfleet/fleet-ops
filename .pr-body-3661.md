# Seat-key phantom guard (fleet-ops#3661)

## Problem

A phantom seat `devin__swe-1-7-.out.json` entered the seat ledger with
`"model":"swe-1-7-.out"` — a probe-output filename fragment, not a real
seat. `fleet-seat-comeback-release` enumerated every `$LEDGER/*__*.json`,
trusted the filename, and probed `devin/swe-1-7-.out` every sweep; the
repair dispatcher picked it too. Every ledger writer and every prober must
now validate the provider/model pair against `config/seat-caps.json`
(`providers.<p>.models.<m>`) and LOUD-reject a phantom key instead of
writing, probing, or dispatching it.

## What changed

- **Every seat-ledger writer rejects a key absent from seat-caps.json**
  with `LOUD SEAT-KEY-INVALID <p>/<m> writer=<fn>` and writes nothing:
  `mark_seat_spawn_fail`, `mark_seat_empty_run`, `mark_seat_quota_bench`,
  `mark_seat_overload_bench`, `mark_seat_hang_bench`,
  `_seat_write_spawn_bench` and `write_parked_ledger` in `lib/seat-lib.sh`;
  and `write_ledger` in `bin/fleet-seat-live-validate`.
- **comeback-release enumeration skips + LOUD** — the sweep never probes a
  phantom key, and the expired/breach recount excludes it.
- **alert-repair seat pick skips + LOUD** — never dispatches a phantom key.
- **`writer` field added to every ledger record** so the next phantom names
  its author.
- Guard is fail-open when the caps file is missing (hosted CI / no deploy),
  so a missing allowlist never bricks a probe or dispatch path.
