## Cap the eight zero-yield worker seats to 0 (fleet-ops#4271)

The session-waste population study (#4260) showed seven seats took **637 picks (26% of all runs)** and produced **15 PRs (3%)** over 2026-09-01..09-07. Each pick still costs a claim cycle and a `RestartSec=240` delay on a live issue, so an infra-dying or low-yield seat must not be picked while a working one is free.

### Config change (`config/seat-caps.json`)

Capped the eight seats to `cap: 0` with `intentional_cap_zero: "yield"` and a dated ledger reason citing the session-waste data (runs, PRs, PR/run, slot-min per PR). The re-audition path (yield gate #3251) is the only way back in — these seats never auto-expire.

### Detector (`tests/seat-caps-zero-yield.test.sh`)

A new test asserts **no seat with `cap > 0` holds 0 PRs over >= 20 picks** (trailing-7-day yield), so the next zero-yield seat is caught without a human reading a table. It reads the live config and a seat-yield fixture, and fails if any zero-yield seat (>= 20 picks, 0 PRs) is not capped 0 with `intentional_cap_zero=yield` and a dated reason. Hosted by `tests/seat-lib.test.sh`.

### Supporting changes

- `lib/seat-lib.sh`: classify `intentional_cap_zero=yield` as **intentional** (never auto-expired; re-audition only via the yield gate #3251).

- `tests/seat-caps-citation.test.sh`: rule 6 skips free-class model overrides on metered providers (a free model costs nothing, so the spend-protection evidence threshold does not apply).
