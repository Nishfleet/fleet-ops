fix(failed-command): lock the live #784 `systemctl --user status` failed-unit walked-past shape

The session-close lint (fleet-ops#535) auto-filed #784 from the
2026-08-27T01:49:30 session (slug 01a040e8-7030-72f9-bb6c-ed7efd812bee):
an unpiped `systemctl --user status 'fleet-deploy-check.service' --no-pager`
call returned 3 (systemd's documented not-active code) with `× unit` and
`Active: failed (Result: exit-code)`, the toolResult was isError=true, and
the assistant continued in a thinking block plus a git-status probe without
naming the failure in user-facing text.

The detector already correctly flags the live #784 class: the command text
does not match `BENIGN_STAGE_RE` (no grep/rg/diff), `isError` is true,
exit 3 is a real failure, and later thinking is not a flag (`_text_chunks`
only reads `type=text`). This PR pins that shape so a future refactor
cannot regress it. No `lib/failed-command-flagged.py` change — a
suppression would silence a real signal. The auto-filed issue closes via
observe-to-close (fleet-ops#758) when the origin session is no longer a
finding (still reported on the 2026-08-27T03:50:59Z detector tick).

Filed along the way (not this PR): Nishfleet/fleet-ops#879 — the same
status call piped through `head` is missed because Pi bash has no
pipefail, so the pipeline exits 0.
