## Summary

- The `close-duplicates` sweep re-posted the SAME `possible-duplicate-of` marker comment every tick on protected duplicates. A protected canonical (`agent-in-progress` / `agent-blocked` / `red-on-main` / `critical-path` / owner-authored) can never be closed, so the comment-only branch fired every run with no memory of the prior marker. **#3728 accumulated ~20 identical marker comments** over ~20 sweep ticks because its canonical (#3587) was `agent-in-progress` (protected).
- Add `issue_has_dup_marker()`: fetch the issue's comments via `gh issue view --json comments` and return True if a `possible-duplicate-of: <canon_ref>` marker already points at this canonical. The comment-only branch skips (action=`skip`, reason=`already-marked:<reason>`) when the marker is already present. Fail-open: a gh error returns False so the marker is still posted — the idempotency is a best-effort spam cut, not a gate that can suppress the duplicate signal on a transient gh failure. A marker for a DIFFERENT canonical does not suppress the comment.
