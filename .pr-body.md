## Why

The #4540 park detector stops the slow-spaced re-claim spin for protected-merged issues, but its preconditions were narrowed to issues that are protected (owner-authored or critical-path) AND carry a merged claim-branch delivery PR. A bot-authored land-or-close ticket misses both: it meets acceptance by driving OTHER PRs to merge (#1992, #4070), the worker cannot `gh issue close` so it stays OPEN, and it opens no claim/issue-$N PR of its own. Live case #4417 was re-claimed 18 times in ~16h. Every anti-loop gate misses it: #2462 (MAX_RECLAIMS) resets on any non-empty-output run and #2772 (window) sees only ~3 claims per 2h at the 15-min cooldown spacing.

## Scope

- `lib/pi-intake-tick.sh` — add an `elif` land-or-close branch to the #4540 park detector. Past `PARK_MAX_CLAIMS`, a NON-protected issue (`_park_protected == 0`: bot-authored, no `critical-path`) whose `termination:` clause names other PRs (the `gh pr view` signature) and that has NO merged claim-branch delivery PR is parked under `awaiting-runtime-gate` (removed from `agent-ready`) with a land-or-close-specific comment (`skipped-parked-land-or-close`). The protected-merged `if` branch is unchanged.
- `tests/pi-intake-tick-land-or-close-park.test.sh` — new test pinning the land-or-close park contract.

The fix is additive (only adds a park condition); it can never break an existing claim, only over-park in the worst case (the issue stays open, unparked when the label clears).
