## What

Add the reusable surface-audit scaffolding for fleet-ops#1198. The visual-quality program (waves 2-4) targets public, logged-out, light-theme pages; four defects reached a live paying account on 0509 on 2026-08-27 (Nishfleet/0509 PRs #1298, #1300, #1301) that the design would have caught **none** of. This PR adds two axes — **theme** `{light, dark}` and **auth state** `{logged-out, free, scout, starter, agency, expired}` — to the matrix, everywhere it appears.

The scaffolding is the boilerplate. Per-product deterministic rules (contrast, control-row alignment, gutter alignment, horizontal overflow, tap targets, focus rings) live in each consumer repo's `scripts/surface-audit.mjs`, per Nishfleet/0509#1302.

## Schema

```json
{
  "matrix": {
    "themes": ["light", "dark"],
    "authStates": ["logged-out", "free", "scout", "starter", "agency", "expired"],
    "viewports": [
      { "name": "mobile", "width": 390, "height": 844 },
      { "name": "desktop", "width": 1440, "height": 900 },
      { "name": "wide", "width": 2000, "height": 900 }
    ],
    "routes": ["/", "/app", "/search"]
  },
  "auth": {
    "method": "cookie",
    "cookieName": "f9_e2e_fixture",
    "fixtureScript": "scripts/e2e-prepare-local.mjs"
  },
  "serve": {
    "command": "npm run preview -- --port 4180 --strictPort",
    "port": 4180
  }
}
```

Repos without `surface-audit.json` self-skip with `::notice::`, no Node install wasted — matches the wave-1 `visual-check.yml` pattern.

## Layout rules

- The reusable never starts the product server itself. Only the consumer knows the right command + readiness probe, and a hard-coded `npm run preview` would freeze every non-Vite product's audit.
- Theme and auth-state are inputs to the consumer's audit script, not branches inside the reusable. The reusable is the boilerplate; the rules live in the consumer.
- Live credentials must NOT cross CI. The cookie-based fixture sign-in pattern (proven on 0509's `e2e/local-authenticated.spec.ts`) is the supported shape.

## Out of scope here

- The fourth defect (a page making a claim that is false for the viewer) needs a reader, not a rule. That is a separate issue against the fleet's visual-quality program — deliberately not folded in, so this one stays deterministic, free, and blocking. (Same call as 0509#1302 made.)
- Propagation to existing repos via `repo-standards-sync.yml` is a follow-up — that workflow lives in `.github/workflows/**` and the worker cannot push to it. The thin caller is shipped via `template/` and bootstrapped into new repos; a Workflows-scope token lands the repo-standards-sync group when the reusable is callable.
