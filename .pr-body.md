## What changed and why

Part 1/2 of #3264 (child of #3127). Part 2/2 (#3709, merged as #3796) already owns the no-capable-seat fallback; this part adds the reviewer round itself. Evidence for why the gate matters: fleet-ops#3812 — a worker's "Test PR" carrying one text file was armed and merged like any App PR; a reviewer round before the arm is what stops that.

Product PRs — repos marked `product` in config/intake-repos.json (0509, siterep-public, inish-site; fleet-ops PRs exempt) — now get exactly ONE reviewer round before the auto-merge arm: `Use reviewer to review the diff origin/main...HEAD against the issue acceptance and the repo tests`, run on the first usable entry of `senior_seats_in_order` (#3121, cursor/cursor-grok-4.6-high first), resolved by the existing `find_senior_seat` seat lookup and passed explicitly to the subagent call because the extension inherits the parent seat by default — never the worker's own seat. Findings land in the PR body in the four review-adjudication buckets (Act on / Consider / Noted / Dismissed-with-reason) with the reviewer seat named; Act-on items are fixed before arming. One round only, no loops.

- **prompts/worker.md**: new step 8 "Reviewer round (product repos only)" precedes the arm — `bin/fleet-review-arm-check` exit 1 means no senior seat is usable, so the round is skipped and the existing step-9 fallback (`review: skipped, no capable seat`) applies; exit 0 resolves the seat via `find_senior_seat` (lib/seat-lib.sh, prints provider<TAB>model) and runs the stock `reviewer` subagent on that seat. Arm renumbered to step 9, print to step 10; manager-mode references updated (Steps 1-10 / Steps 6-10).
- **config/intake-repos.json**: `product: true` on 0509 (repos) and siterep-public + inish-site (deferred) — the marking step 8 keys off. fleet-ops deliberately unmarked: control-plane PRs are exempt.
- **tests/worker-prompt-reviewer-round.test.sh** (new): prompt-contract lock PLUS the accept's replay drill — a fake product PR + fake reviewer verdict carrying one Act-on item: the arm refuses when the body lacks the reviewer seat and buckets (State A), refuses while the Act-on item is UNRESOLVED even with buckets + seat (State A2), and allows once the Act-on item is resolved with four buckets + seat name (State B).
- **tests/pi-issue-start.test.sh**: hosts the new test (fleet-ops#82 — workers have no Workflows permission, so it cannot get its own ci.yml line).
