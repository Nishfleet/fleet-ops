## Blind-spot detector: weekly review opens with "Caught by hand this week"

The judge and the weekly review only see what measure.sh measures. On
2026-09-08 Nish caught 19 red deploys, 55 discarded issues, a starving pool
and a $400 idle pool **by hand**, all under green reports. This PR puts a
standing detector on the existing weekly review + hourly fable-check rails
(no new timer), so those blind spots surface and get a measure line instead
of living only in Nish's head.

### What changed

1. **`prompts/weekly-fleet-review.md`** — the FIRST section is now
   **"Caught by hand this week"**. Every finding from the week's
   `decisions-ledger.md` entries, the judge's `new-measure:` header lines,
   and Nish's Telegram/chat corrections is listed; each gets a `measure.sh`
   line (citing the commit) or an `agent-ready` measure issue in the review's
   ≤5 actions. A finding caught by hand TWICE with no `measure.sh` line is a
   RED review.
2. **`prompts/fable-check.md`** (new) — the repo copy of the hourly judge
   brief, so the `new-measure:` header rule survives a brief rebuild (it was
   previously only in the agent-state live packet).
3. **`libexec/fleet-blindspot-count.py`** (new) — the measure.sh helper that
   emits `new_measures_7d=<n>` and `caught_by_hand_7d=<n>` from the
   decisions-ledger + fable-state. Metric invariant every run/week:
   `new_measures_7d >= caught_by_hand_7d` — every caught-by-hand item gets a
   measure line.
4. **Tests** — `tests/fleet-blindspot-count.test.sh` (hermetic contract:
   window counting, out-of-window exclusion, red balance on an uncovered
   catch, missing sources yield 0 not a guess), registered in
   `tests/seat-lib.test.sh` for CI (workers cannot push workflows).
5. **MANIFEST + `config/role-quality-gates.json`** — register the helper and
   gate the new fable-check prompt under a `judge` role.
