## Summary

Vault notes that assert live state (unit status, seat caps, red/green on main, PR merged/open, lane counts) now fail unless frontmatter carries `check-command` and a fresh `observed` timestamp. A pointer or procedure with no live-state claim passes. Fenced examples are treated as samples, not claims.

`lib/vault-lint.py` is the lint. `--check` exits 1 on a violation (worker pre-write). `--report` prints Markdown and always exits 0 (heartbeat can surface drift without going red). `--pre-write` exits 2 and prints the report so a capture wrapper can refuse the note before it is committed. Slice 4 (`siterep-vault-capture`, #1265) should call `--pre-write`.

Class TTLs match slice 2 (#1263): drill-status 5m, seat-caps 1h, seat-health 1m, decision-ledger 7d, evidence 30d, procedure 90d. An explicit `ttl:` overrides the class default.

Hosted in CI via `tests/rule-enforcement.test.sh` (workers cannot edit `.github/workflows/**`).

Follow-up filed: #1309 (`tests/alert-repair-claim-mutex.test.sh` is unhosted on origin/main). Not this slice.
