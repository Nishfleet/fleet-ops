## Why

`tailscale debug netmap` rc=1 was treated as confirmed watcher-broken. The same alarm was filed and closed at least five times (#1437 #1447 #1733 #2333 #3955). Live `bin/fleet-tailscale-acl-canary` exits 0 most ticks. The flap is a LocalAPI blip, not a broken watch.

Retry the live fetch (3 attempts, 10s apart, ~30s). Persistent failure exits 2 as unknown and files `tailscale-acl-canary: netmap-unknown`. Confirmed watcher-broken and lockdown-broken stay exit 1. Unknown never passes: a stale or empty netmap is discarded.

## Scope

- `bin/fleet-tailscale-acl-canary`: retry live netmap; exit 2 + `netmap-unknown` marker on persistent rc=1; fixture path unchanged.
- `bin/fleet-heartbeat-tier1` block 28: log `rc=2 netmap-unknown` separately; still fail the unit (unknown must not pass).
- `config/rule-enforcement.json` `led-tailscale`: name the distinct marker so the refile detector can tell churn from a real recurrence.
- `tests/fleet-tailscale-acl-canary.test.sh`: (a) transient rc=1 then success exits 0, (b) persistent rc=1 exits 2, (c) clean-but-stale netmap still fails, (d) files `netmap-unknown` not `watcher-broken`.

Out of scope: changing PacketFilter honesty, sudo netmap, or lockdown-broken.

## Tradeoffs

Heartbeat can spend ~20s sleeping on a real LocalAPI outage (TimeoutStartSec=45min). Tests set `FLEET_TAILSCALE_NETMAP_RETRY_SLEEP_S=0`. Persistent unknown still fails the unit, so a dead watch cannot look green.

## Blast radius

led-tailscale / heartbeat block 28. A one-tick netmap blip no longer files watcher-broken. A 30s outage still fails loud, with a different marker. Rollback is revert of this commit.
