test(metrics): pin seat-health age UTC parse + FleetPiSeatHealthStale >1800 rule (fleet-ops#3239)

The implementation for fleet-ops#3111/#3239 is already on main:
`fleet_pi_seat_health_age_seconds`, UTC-agnostic `calendar.timegm` parsing in
`libexec/fleet-metrics-export.py::_read_seat`, and the
`FleetPiSeatHealthStale` rule in `config/fleet_rules.yml`. This PR lands the
verifying test that was missing from that earlier work.

## What changed

- `tests/fleet-metrics-export.test.sh` section 9b:
  - Proves a fresh UTC `observed_at` is parsed as ~60s old under
    `TZ=Asia/Kolkata`, not ~19800s (the `time.mktime` local-TZ bug class
    fixed in console PR #3520).
  - Proves absent/unparseable `pi-seat-health.json` returns `(0, None)` and
    the exporter emits age `-1` (UNKNOWN).
  - Proves `FleetPiSeatHealthStale` fires on `age == -1` or `age > 1800`.
