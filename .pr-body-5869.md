terminal/unit) plus the issue receipt: start_ts = the packet's dispatch
instant, end_ts = the disposal instant, terminal=escalated (the legal
terminal the chain reached), unit=escalation-drain. Consumers select only
alertname+end_ts, so the extra key is additive; the ledger stays
append-only. Fail-open unchanged: no disposition -> no record; DRY writes
nothing. A later same-alertname re-dispatch dispatched before end_ts is
absorbed under the terminal by the existing consumed-rule — the stuck set
returns to 0 on the next run instead of the backlog trending up.
