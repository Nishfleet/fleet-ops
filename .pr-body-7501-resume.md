## Why

PR #7348 merged 25 seconds after its required gate check failed. The old measure probe checked only gate-path changes and used today's final check result, which can miss an escape after a later rerun.

Relates to #7501. Successor to #7535: GitHub mechanically refuses to reopen that PR after its head branch was recreated ("state cannot be changed. The claim/issue-7501 branch was force-pushed or recreated"), so this PR resumes it with the same retained records, rebased onto current main.

## Scope

Replace the existing `measure.sh` gate-escapes block with a sourced helper. Read required contexts and enforcement from the REST branch endpoint, which works with the worker token. Read all check attempts and commit statuses on each merged PR head. Count failure/cancelled verdicts completed before merge, not failures completed afterward. Print a LOUD receipt naming PR, check, head SHA, merge time and gap in seconds. Keep the aggregate metric and add per-repo counts.

No new timer, service, workflow, required context, admin bypass or protection change. MANIFEST installs the helper next to the existing measure libraries. The regression runs through the existing gate-arm-guard P14 entry.

## Tradeoffs

Current branch metadata does not prove which contexts were required historically or the merger's admin status. Output says `policy_at_merge=unverified` and `admin_bypass=possible`, not proven. A rerun started after merge cannot erase an earlier failure. A rerun already pending at merge is not counted as a failure/cancellation.

Reads cost two REST calls per merged head plus branch and paginated PR-list calls. No cache or new poller was added.
