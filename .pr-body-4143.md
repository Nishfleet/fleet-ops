## Retire venue-claim + open-question to GitHub native claim/lock/queue

Closes #4143. Relates to #4155 (duplicate of #4143) and #4140 (umbrella).

`venue-claim` (1,008 lines) and `open-question` (802 lines) were live-only,
orphaned claim/lock/queue scripts (no systemd units, no data dir). The fleet
already runs claim/lock/queue on GitHub issue assignment + Projects, Actions
concurrency groups, and flock/systemd for local locks. Both scripts are wiped
from the live path (`~/.local/bin/venue-claim`, `~/.local/bin/open-question`,
`~/.local/bin/venue-ledger`, `~/.local/state/open-questions/`).

### Consumer mapping (what replaced what)

- `venue-claim` (venue-submission ledger + guard) -> GitHub issue assignment +
  Projects (each venue submission tracked as an issue on a Project board) +
  Actions concurrency groups (rate limit / no concurrent submissions) +
  flock/systemd for the local lock. The GEO/AEO policy gate stays in
  `config/geo-aeo-policy.json`.
- `open-question` (open-question state machine) -> GitHub issue assignment +
  Projects (each open question becomes an issue, tracked on a Project board).
- `venue-ledger` (compat wrapper) -> deleted; it only delegated to venue-claim.
