## What

`bin/vps-weekly-update` was git-tracked **non-executable** (`100644`). install.sh
symlinks it to `~/.local/bin/vps-weekly-update`, and the systemd unit runs it
directly via `ExecStart`. A non-executable `ExecStart` target makes systemd abort
the service with **status `203/EXEC`** — so the weekly maintenance window never
actually ran, no reboot happened, and `/var/run/reboot-required` was never
cleared (uptime 7.2 d, kernel patches pending).

## Determination (per the issue)

The window does **NOT** skip reboots when agents are active. It already has the
full drain-and-reboot path (`bin/vps-weekly-update` steps 1→4: quiesce/pause →
apt/npm/docker/self-updaters → verify → if `/var/run/reboot-required` exists,
notify + `systemctl reboot`, with `resume-after-boot` on the post-reboot tail).
So "make it drain-and-reboot" is already satisfied. The real fault is that the
window **never runs** because the script lost its executable bit.

Live proof (netcup-rs2000):
- `vps-weekly-update.service: Main process exited, code=exited, status=203/EXEC`
- symlink `~/.local/bin/vps-weekly-update` -> deploy-clone `bin/vps-weekly-update`, mode `-rw-rw-r--` (not executable)
- direct exec as the unit would: `Permission denied` (rc 126; systemd maps to 203/EXEC)
- git blob mode for `bin/vps-weekly-update` = `100644`

## Fix

1. Restore the executable bit: `bin/vps-weekly-update` now git-tracked `100755`.
2. Guard (fleet-ops#366 mechanical fix): extend `tests/fleet-ops-1160-regression.test.sh`
   (already hosted in `tests/ci-standards-audit.test.sh`, so it runs in CI without a
   workflow edit) with a section that fails if `bin/vps-weekly-update` /
   `bin/vps-post-reboot-verify` are git-tracked non-executable, plus a class lock
   that every non-`.py`/`.ts` script under `bin/` must be `100755`.
