## Summary

Diagnoses the 2026-09-03/04 zero-merge window (fleet-ops#3082) and ships a
prevention mechanism so the class cannot repeat as a 27h silent wedge.

### Diagnosis (root cause, from live journal + dispatch ledger)

- **Merge gap:** no fleet-ops PR merged from 2026-09-02 21:33Z to 2026-09-04
  07:06Z (~33h). The snapshot was taken 2026-09-03 21:45Z, ~24h in.
- **Workers started but did not land:** 281 `pi-issue@fleet-ops-*` unit starts
  on 2026-09-03, 245 exited status=1 (87%), 37 finished, **0 merges**. The
  heartbeat throughput line read `merged_product_PRs=0` every tick.
- **Root cause — broken `pi` binary:** starting 2026-09-03 ~04:35Z,
  `/home/nish/.local/bin/pi` was unexecutable. Every alert-repair unit dispatched
  to self-heal the `FleetUndersaturated` alarm died with
  `Failed to execute /home/nish/.local/bin/pi: Exec format error` (203/EXEC),
  31 such events across the window. The undersaturation repair cycled
  `UNDERSAT-REPAIR reason=full-wedge` -> `UNDERSAT-FAIL-LOUD` every tick without
  ever naming the cause; `running=0` persisted because every worker it started
  also could not exec pi.
- **Recovery:** `pi` was reinstalled at 2026-09-04 ~06:52Z (symlink mtime);
  merges resumed 07:04Z. Fleet is healthy now (no failed units, seat healthy).
- **Contributing factor:** the spec-gate refused ~15 agent-ready issues because
  pre-existing tests fail on main — separate issues, not the wedge cause.

### Fix (prevention mechanism — edit to an existing organ, no new machinery)

`bin/fleet-heartbeat-undersaturation` now probes the `pi` binary at the start
of the repair path. If `pi --version` fails (missing, not executable, or
exec-format error), the repair is futile — every repair action spawns pi-based
workers — so the FIRST wedged tick fails LOUD with
`reason=pi-binary-broken` and attempts no repair. This names the cause
instantly instead of cycling REPAIR->FAIL-LOUD for 27h until a human notices.

Test seam `PI_BIN` lets the existing scenarios point at a working stub (so a
runner without `/home/nish/.local/bin/pi` is not falsely fail-loud'd); scenario
10 overrides it with a broken stub and proves the instant named fail-loud.
