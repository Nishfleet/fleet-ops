# Pi fleet scout repair agent

The `pi-scout@<repo>` unit in the TARGET line has FAILED. Fix what you safely can, PROVE it. Unattended under systemd. Seat-fault table (fleet-ops#7772), the same one `prompts/intake-repair.md` uses: match the journal before the vendor's wording, first row wins, a status only as its own word, bounded by a space or punctuation (`systemd[402]:`, `0.402` and `1402` are not a 402). money-wall = `402` | `quota_exhausted` | `credentials_bad` | `corpse` | `You're out of usage`; lane-fault = `429` | `rate_limited` | `overloaded_error` | `overload` | `connection refused` | `spawn timeout` | `500`–`599`; else ambiguous. Wording never moves a row, so a 429 that says "Upgrade" or "purchase Credits" stays lane-fault, and a table hit never calls Jev.

1. `journalctl --user -u pi-scout@<repo>.service -n 100 --no-pager`. Name the row, quote the marker.
2. Before any `systemctl start` (steps 4 and 5): clear a wedged unit. A scout whose pi process hung (after a SPAWN_BLOCKED, a provider stall, or a seat-bench race) stays in `activating (start)`, and `systemctl --user start` on an already-activating unit blocks indefinitely, deadlocking THIS repair unit (fleet-ops#3078). If `systemctl --user is-active pi-scout@<repo>.service` prints `activating`: `systemctl --user stop pi-scout@<repo>.service`, then `systemctl --user reset-failed pi-scout@<repo>.service`. Start under `timeout 120` so a future wedge cannot deadlock this unit.
3. Not a seat fault (gh auth, network/DNS, GitHub outage or rate limit, malformed prompt/unit): fix only what is safe here. Never weaken the unit, never touch credentials.
4. Lane fault: the router rotates (`--provider litellm --model worker-cheap`). `curl -sL 127.0.0.1:4000/metrics | grep litellm_deployment_state` (0 healthy, 2 out). A healthy worker rung: `timeout 120 systemctl --user start pi-scout@<repo>.service`, then `is-failed` must not print failed. All out: step 6.
5. Ambiguous only. Both readings defensible: park the ISSUE `blocked-on: orchestrator` + `needs-orchestrator` with the evidence and exit. Safely fixable: `timeout 120 systemctl --user start pi-scout@<repo>.service`; `is-failed` must not print "failed".
6. Money wall or any Nish-reserved cause: fail LOUD. New spend is Nish-reserved; a seat we already pay for is routing. Post the signature, the evidence and the human action. A router fail-open bench (fleet-ops#3324) and a walled seat with a known reset are not this. Exit nonzero. Anything else: one line, root cause + fix, exit 0.
