# Release assets (the release-assets job in .github/workflows/agent.yml, fleet-ops#8871)

A release was just published in the product repo checked out here (at the tag; PRODUCT_REPO and RELEASE_TAG are in the environment). You make two assets in the product's own look and open one PR. Stock pieces only: no scripts, hooks or helper files anywhere (Nishfleet/0509#3679). Never print secret values. Never merge or arm the PR you open.

1. Read `DESIGN.md` at the repo root. It is the product's visual language and voice; both assets must match it. If `DESIGN.md` is missing, print `release-assets: no DESIGN.md` and exit 1.
2. OG/social card, 1200x630 PNG, saved as `public/og/<RELEASE_TAG>.png`. Image model: Cloudflare Workers AI `@cf/black-forest-labs/flux-1-schnell`, reachable on the current free plan (one image is well inside the free daily neuron allocation; no paid tier, zero-revenue rule). Call it with curl: POST `https://api.cloudflare.com/client/v4/accounts/<account-id>/ai/run/@cf/black-forest-labs/flux-1-schnell`, header `Authorization: Bearer <token>`, body `{"prompt": "<card art direction from DESIGN.md; no words in the image>"}`. Read the token and account id from `~/.config/cloudflare/deploy-ci.env` (grep the file for the variable names; never echo the values; if the file names no account id, GET `https://api.cloudflare.com/client/v4/accounts` with the token and use the first account's id). The response JSON carries the PNG base64 in `.result.image` — decode it into the file. If the call answers HTTP 403, retry once with model `@cf/stabilityai/stable-diffusion-xl-base-1.0`. If both answer 403, print `release-assets: workers-ai 403` and exit 1 — the token lacks Workers AI scope and a wider token is Nish's dashboard call, nobody else's.
3. Changelog post at `docs/changelog/<RELEASE_TAG>.md`: 80-150 words in the product's voice per DESIGN.md — what shipped (read the release notes with `gh release view <RELEASE_TAG> -R Nishfleet/<PRODUCT_REPO>`), one line on why it matters, no adjectives the DESIGN.md voice would not use.
4. `git checkout -b release-assets/<RELEASE_TAG>`, commit both files, push, and open a PR titled `release <RELEASE_TAG>: OG card + changelog post` with the card image inline in the body. The branch name is the job's idempotency marker — use it exactly. Do NOT arm auto-merge and do NOT merge: the card is brand-facing and brand is Nish's class (AGENTS.md hard lines) — the PR is his review gate. Print `release-assets: pr=<url>` as your last line; that line is the job's completed-run signature.
