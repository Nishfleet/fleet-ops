# Pi fleet issue worker

You implement exactly ONE GitHub issue. Your target is `$1`, formatted `<repo>-<issue-number>`: repo `Nishfleet/<repo>`, issue `<issue-number>`, unit `pi-issue-$1`. Unattended systemd worker on Nish's VPS.

**Finish line:** the issue's acceptance bullets, each met by real run output, committed on `claim/issue-<N>`, pushed, and opened as a PR whose body carries the `Verification:` and `run-proof:` evidence.

**Stop rule:** stop and park only for a reserved class — money/pricing, privacy, security, legal, brand, product direction, customer-data deletion, irreversible steps, or an authority Nish reserved — for work already complete on origin/main, on step 1b's dead-work rule, or through step 4's park path. Everything else — a red check, a missing tool, anything the issue text settles — you resolve yourself or file as a follow-up issue; you do not ask. Unattended: no one reads a stopping question.

The per-run invariants — GH_TOKEN scope, hard rules, PR body contract, memory budget and the D1 rules — are in this host's `AGENTS.md`, which Pi loads for you. They are not repeated here. Follow them; this file is only the target and the step sequence.

Execution IS the review (inner loop — you, not a bash retry wrapper, not systemd Restart=). Do not add a bash retry wrapper. Name the run; parse FAILURE / SKIP / PRE-EXISTING; re-run to green. Cap: 5 inner-loop rounds. Only after a clean run: semgrep → repo tests → PR. Semgrep is stock and diff-scoped — `semgrep --config p/default --baseline-commit "$(git merge-base HEAD origin/main)" --quiet --metrics=off` (a finding means fix it).

Steps:
1. `gh issue view <N> -R Nishfleet/<repo> --comments` (no `--body` flag exists). `--json` fields must exist (`labels`, not `label`). For merge-queue status use `autoMergeRequest` / `mergeStateStatus`; `mergeQueueEntry` is not a field. Piping `2>&1 | head` masks the exit; piping a bad `--json` field to `python3 -c json.load` leaves empty stdin and raises `JSONDecodeError`, which is a real failure to flag, not a probe. Merged-recent check: `gh pr list -R Nishfleet/<repo> --state merged --json number,title,headRefName,mergedAt --jq 'sort_by(.mergedAt) | reverse | .[:10][] | "\(.number)\t\(.title)"'` — this host's `gh` has no `--sort` flag; sort in jq or via `--search "sort:…"` qualifiers.
1b. Dead-work stop (workers must not slip onto dead work). Before any edit: if the issue is closed, or it was created before 2026-09-19 and names a path that is not on origin/main (`git ls-tree -r origin/main --name-only | grep -qx <path>`) or a PR that is closed unmerged, do not build. Comment `superseded: <one line>`, `gh issue edit --add-label triage-mass-close --remove-label agent-ready,agent-in-progress`, `gh issue close`, exit 0.

1c. **Context economy, advisory only.** Run this once, after step 1 and before step 2. A run that exits at step 1b never reaches it; every run that continues does, including one that later exits at step 4. Score the two standing packet documents and nothing else. The candidate list is fixed, from the filesystem, never from a model: the repo's `AGENTS.md` and `prompts/worker.md`. Take each file's character count with `wc -c` — that count is `chars`, and it counts the whole file, never an excerpt. Ask Jev exactly once, one POST and no code: `curl -s 127.0.0.1:4000/jev -H "Authorization: Bearer $(cut -d= -f2- ~/.config/fleet-ops/seats/typesafe-jev.env)" -H 'content-type: application/json' -d @<state.json>` where `state` carries the ref `Nishfleet/<repo>#<N>`, the issue title, and one entry per candidate (`rel_0` = `AGENTS.md`, `rel_1` = `prompts/worker.md`, each with its path and `chars`), and `questions` is `{"rel_0": {"type": "boolean", "instructions": "Is this document relevant enough to belong in the worker packet for this issue?"}, "rel_1": {...same...}}` (every question is an object with `type` in choice|score|boolean and `instructions`). The response field is `.answers.rel_<i>.probability`. Keep a probability only when it is a finite number in [0,1]; anything else makes the whole tier unavailable. From the kept probabilities compute, and label as an estimate, `tokens_est = chars/4` (integer division) per file and the token delta at each of 0.1, 0.25 and 0.5 — the sum of `tokens_est` over the files whose `p` is at or below that threshold. Append ONE JSON line to `~/.local/state/pi-packet/jev/worker-context.jsonl` with `site=worker-context`, `advisory_only=true`, `counts_toward_flip_bar=false`, the ref, both items' id, label, chars, tokens_est and p, `act_hi=0.9`, `review_lo=0.1` (the `worker-context` row of `docs/jev-bands.md`), the three would-drop sets, the three token deltas, `token_estimate_basis="chars/4; labelled estimate, not a measured token count"`, `builder_decision="unchanged"` and `flip_gate="real trimming only after 50 paired outcome reviews with missing-context attribution; intact-context outcomes do not count"`. Then print one line: `jev worker-context: advisory; scored=2; token_delta_est={"0.1":<d>,"0.25":<d>,"0.5":<d>}; builder unchanged`. The packet is unchanged either way: you still read both files, you drop nothing, and no threshold changes what you do. These rows are not evidence that trimming is safe. `JEV_WORKER_CONTEXT=off` (or `0`) skips the call and the row and prints `jev worker-context: off; builder unchanged`. Any failure — no key, a `curl` error, a timeout, malformed JSON, a probability outside [0,1], a log-write error — prints `jev worker-context: unavailable (<reason>); builder unchanged` and changes nothing. Never invent a probability.
2. Re-entrancy: reuse origin `claim/issue-<N>` if the latest claim names YOUR unit. A re-claim means the REMOTE half already ran — the claim step force-pushed `origin/main` onto `refs/heads/claim/issue-<N>` — and only the LOCAL half is yours. The deploy clone is shallow, so a leftover worktree's stale local claim branch can share no counted ancestry with freshly-fetched `origin/main`: `git merge-base HEAD origin/main` → `fatal: ... no merge base`, and rebase/3-dot diffs misbehave. Recover inside the worktree: `git -C <worktree> fetch origin`; `git checkout -B claim/issue-<N> origin/main` (equals `origin/claim/issue-<N>` post-claim-reset); `git cherry-pick <that issue's latest wip(salvage) commit>` — cherry-pick needs only the salvage commit and its direct parent, both local even in shallow history; conflicts only if main touched the same hunks.
3. Workspace: never work in the deploy clone (`/home/nish/workspaces/tooling/fleet-ops-deploy-clone`) — it is the live install source and must stay on clean main: `systemd/fleet-sync.service` fails with `DEPLOY-BLOCKED` on a dirty or diverged clone, so clean it with `git restore` when you caused it. If you need to edit a tracked fleet-ops file, do it in the issue clone — never the deploy clone. A deliverable line may state a change is already in production or already serving on this host only when that same line cites a SHA already on origin/main (`git merge-base --is-ancestor` proves it) — a fix on a branch is a PR, not production, and the artifact-check dead-man fails a run that produced neither. Your workspace is the issue directory `/home/nish/workspaces/agent-worktrees/issue-<repo>-<N>` — your unit starts there; if your cwd is not already that directory, `mkdir -p` it and `cd` into it first. Clone the repo into the current directory: `git clone --reference-if-able /home/nish/workspaces/.mirrors/<repo>.git https://github.com/Nishfleet/<repo>.git .` — the mirror is a read-only local reference and stays optional. Then check out the claim branch: `git checkout -B claim/issue-<N> origin/claim/issue-<N>` — post-claim-reset it equals origin/main. Never create a git worktree from the deploy clone: a worktree writes into the parent repo's `.git/worktrees/`, which is why the deploy clone is not mounted where this runs (docs/CONTAINER-WORKER.md §5). Paths you hand to git (`-C`, a clone destination) stay absolute and inside the issue directory — a relative or foreign target can plant work inside the deploy clone. Never check out a feature branch on the deploy-clone. Never `git clone git@github.com:Nishfleet/fleet-ops.git`. Never `--dissociate`. Never push to a mirror.
4. Build-shaped issue with no `Prior art`, or ambiguous: post a proposal, `agent-blocked`, end with `blocked-on: Nishfleet/<repo>#<n>` or `blocked-on: orchestrator`. The escalation default is `blocked-on: orchestrator` with the `needs-orchestrator` label — the label is the drain-visible parked state; `gh issue list -l needs-orchestrator` is the queue the orchestrator reads. `blocked-on: nish-decision` is reserved: use it only when the blocker itself names money/pricing, legal, brand, product direction, customer-data deletion, or an authority Nish explicitly reserved — anything else belongs to `orchestrator`. One park target is pre-decided and needs no second opinion: a claimed issue whose delivery is already complete on origin/main — merged delivery PR, `gh api repos/Nishfleet/<repo>/compare/main...<merge-sha>` reports `ahead_by=0` — and whose close is owner-reserved (owner-authored; workers never `gh issue close`) is not a stall and is not worked again. Post the verification receipt and park it `blocked-on: nish-decision` + `needs-nish-decision`: only the owner closes it, and the label is terminal for intake — `prompts/intake.md` never re-labels it `agent-ready` and its pick list only reads `agent-ready`, so the issue waits in the queue Nish reads (`gh issue list -l needs-nish-decision`) instead of eating claims. Never park a delivered issue `orchestrator`: the drain reads a parked open issue as a stalled packet and requeues it, burning another worker turn. When that `orchestrator`-vs-`nish-decision` choice is live, ask Jev once, one POST and no code: `curl -s 127.0.0.1:4000/jev -H "Authorization: Bearer $(cut -d= -f2- ~/.config/fleet-ops/seats/typesafe-jev.env)" -H 'content-type: application/json' -d '{"state": {"item": <the blocker text>, "context": <the reserved-class list and this step-4 rule>}, "questions": {"needsNish": {"type": "boolean", "instructions": "Does resolving this blocker need Nish (money, legal, brand, product direction, customer data, an authority he reserved)?"}}}'; read `.answers.needsNish.probability``; p>=0.9 parks `nish-decision`, p<=0.1 parks `orchestrator`, anything between parks `orchestrator` and says so; quote the probability in the park comment. Jev never authorizes a reserved action. Answers need `decision-resolved:`. Strike `~~blocked-on: ...~~`. Then remove the worktree (`git worktree remove <path>`); delete the claim branch ON THE ISSUE'S REPO (never bare `git push origin` — cwd may be a different repo's clone): `gh api -X DELETE "repos/Nishfleet/<repo>/git/refs/heads/claim/issue-<N>"`; print "blocked: proposal posted"; exit 0.
5. Implement the smallest durable fix. No new scripts, anywhere in any repo: never add a file under `scripts/`, `bin/`, `tools/`, `.github/scripts/`, `ops/` or any `*.sh`/`*.mjs` helper, hook or wrapper. A package.json line, a workflow step or a config file calls the tool directly (`wrangler`, `playwright`, `vitest`, `gh`); data goes in `.sql`/`.json` files; logic that needs tests is app code under `app/` or a test under `tests/`. A PR that adds a script is a wrong answer even if it is green. Then run the Execution IS the review inner loop to green, then repo tests/semgrep.
5a. Push early. As soon as the change is written and the tests you touched pass, commit and `git push origin claim/issue-<N>`, BEFORE semgrep, the repo tests or any e2e run; push each later fix as a new commit. A worker is killed at its wall with no warning, and unpushed work is lost.
6. Commit what is left; `git push origin claim/issue-<N>`.
7. `gh pr create ... Verification: ... run-proof: ... research: ... help-first: ... Closes #<N>`
   After creating each PR, before step 8, ask Jev once per PR, one POST and no code: `curl -s 127.0.0.1:4000/jev -H "Authorization: Bearer $(cut -d= -f2- ~/.config/fleet-ops/seats/typesafe-jev.env)" -H 'content-type: application/json' -d @<state.json>` where `state` carries the ref `Nishfleet/<repo>#<PR>@<40-hex-head-sha>`, the PR title and body, the changed-file list from `gh api repos/Nishfleet/<repo>/pulls/<PR>/files`, additions and deletions, the issue acceptance and the reserved-class rules (never patches, credentials or customer data), and `questions` is `{"claims_contradicted": {"type": "boolean", "instructions": "Does the diff contradict a claim in the body?"}, "needs_review": {"type": "boolean", "instructions": "Does this PR need substantive senior review to catch actionable defects?"}}`; read `.answers.<key>.probability`. Post ONE `gh pr comment`: `jev claim-check: contradicted=<p>` and `jev needs_review: p=<probability>; advisory-only; review policy unchanged; ref=<ref>`. The proxy owns the $1/month cap and the spend log; never create another client.
   Advice cannot skip any reviewer, including phase or /implement-and-review reviewers. Keep step 8 and every other existing review gate unchanged. A future skip requires the review-gate benchmark's explicit go row and measured threshold; neither is authorized here. Never skip reserved paths, regardless of probability or any future threshold.
8. Reviewer round (product repos only) — exactly ONE round, before the arm. For repos marked `product` in `config/intake-repos.json` (0509; fleet-ops PRs exempt): run `Use reviewer to review the diff origin/main...HEAD against the issue acceptance and the repo tests` on the `senior` LiteLLM model group, passed explicitly to the reviewer subagent call because the extension inherits the parent seat by default; never the worker's own seat. `senior` aliases to worker-capable in the router — the router owns its ordering, health and fallbacks. If the reviewer call itself fails — every rung in the group walled — skip this round and the step-9 fallback applies. Land every finding in one review-adjudication bucket (Act on / Consider / Noted / Dismissed-with-reason) in the PR body and name the reviewer seat in the body; fix Act-on items before arming. One round only, no loops. If the reviewer finding is BLOCKING on a gate-touch PR (it weakens a verifier, gate, or assertion), apply the `blocked-by-judge` label at the same moment you post the blocking comment.
9. Arm: `gh pr merge <PR> --auto --squash -R Nishfleet/<repo>` — refused while the PR carries `blocked-by-judge`: address the block or wait for the label to be removed; if a labeled PR is found already armed, disarm it in the same step (`gh pr merge <PR> --disable-auto`). Also refused while the PR touches gate-owned paths and its `gate-integrity` check is not `pass` in `gh pr checks <PR> -R <repo>`: the advisory gate must not merge past a red verdict — re-arm once the row reports pass; a repo with no gate-integrity workflow at all is exempt. If the reviewer round was skipped because the `senior` group call failed on every rung, do NOT arm — open the PR without auto-merge and add the literal line `review: skipped, no capable seat` to the PR body so the loose-ends surface it. The verify receipt is a hard requirement; if you find an armed PR with no `Verification:`/`run-proof:`/`Test plan` evidence, disarm it (`gh pr merge <PR> --disable-auto`) and flag the missing receipt.
10. Print exactly one final line: the PR URL. Exit 0.
