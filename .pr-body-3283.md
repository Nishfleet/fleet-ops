## Summary
Part 1/3 of fleet-ops#3150 (Metered spend is invisible). Inside the existing
`fleet-metrics-export` tick (no new unit), this exports:

- `fleet_seat_spend_usd{provider,day}` — per-provider, per-UTC-day USD summed
  from the per-message `usage.cost` Pi already writes into every session jsonl
  (the battle-tested spend source). A live check reproduces the reference
  values: openrouter 08-29 $12.52, 08-30 $7.60, 09-01 $5.27, 09-04 $7.47.
- `fleet_seat_credits_remaining_usd{provider}` — each metered vendor's own
  remaining balance where an endpoint exists: OpenRouter `GET /api/v1/credits`
  (remaining = total_credits − total_usage; the endpoint publishes no
  precomputed remainder) and xKiro `/v1/usage` wallet balance.
- xKiro free-tier surface from `/v1/usage` per the issue note:
  `fleet_seat_free_tokens_remaining{provider="xkiro"}` and
  `fleet_seat_credits_held_usd{provider="xkiro"}`.

Sibling parts own the rest: #3284 the Prometheus alert rules in
`config/fleet_rules.yml`, #3285 the digest line. This PR does not touch
`config/fleet_rules.yml`.

## What changed
- `_parse_session_file_for_cost` / `_compute_spend`: read cost from
  `message.usage.cost` (the real Pi session shape — provider lives on
  `model_change` lines), scan all pi sessions with a per-file mtime cache and a
  30-day emission window to bound cardinality.
- `_openrouter_api_key`: read the key pi itself authenticates with
  (`~/.pi/agent/models.json`), env override first.
- Vendor fetches send an identifiable `User-Agent` (xKiro 403s urllib's default
  UA with Python-urllib; curl/Mozilla pass — reproduced live).

## Prior-art / approach notes
Spend comes from Pi's own session `usage.cost` (Nish comment on #3283), not
vendor token-pricing math; balances come from vendor credits endpoints only
where one exists. This reworks the earlier branch state that read cost from the
wrong session field (top-level `usage` / `provider`), which computed zero spend
in production despite a green fixture-only test.
