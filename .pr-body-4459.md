feat(spend): rate card in seat-caps, per-session USD in prepaid-usage, usd_24h in measure.sh + fleet_usd_24h prom metric, $/merged-PR seat table (fleet-ops#4459)

## Why

Blind spot (Nish 2026-09-08 "fix all"): the fleet knew merges/day and nothing
about $/day or $/merged-PR per seat. Console-only meters (Cursor, Alibaba, Pareto)
and remote seats (Devin) leave no local balance; the metered/session seats
(Ollama/Crof/Zenmux/Entrim/Straitly/OpenRouter) carry per-call `usage` in the
session jsonl that was never summed into dollars.

This PR adds a rate-card × session-usage spend rail on existing organs
(prepaid-usage counter, session jsonl, seat-caps price fields, measure.sh,
fleet-metrics export) — no new timers.

## What

1. **Rate card** in `config/seat-caps.json` per metered/prepaid-quota provider:
   `usd_per_1m_input`, `usd_per_1m_output`, `usd_per_1m_cached`, each carrying a
   `_rate_card` source citing the measurement + date (crof, minimax, runinfra,
   entrim, straitly, xai-oauth). Flat prepaid seats stay `flat_usd_per_month: null`
   and report `UNAVAILABLE:<why>` — never a fabricated $0 (required).
2. **Per-session spend line**: at run end `pi-issue-run` sums the session jsonl
   usage × rate card into the existing prepaid-usage counter as `usd`
   (`lib/seat-lib.sh _record_prepaid_usd`). Remote-agent seats (Devin) and seats
   with no rate card record `usd=UNAVAILABLE:<why>` — not $0.
3. **measure.sh** prints `usd_24h: metered=<n> flat_share=<n> unavailable=<seats>`
   and `usd_per_merged_pr: <n>`; both also export to fleet-metrics prom as
   `fleet_usd_24h` / `fleet_usd_per_merged_pr`. The math lives in one shared
   helper (`lib/fleet_usd.py`) so measure.sh and the exporter cannot drift.
4. **Weekly**: `prompts/weekly-fleet-review.md` builds the seat table as
   $/merged-PR per seat that week and names the worst seat.

## Scope

- `config/seat-caps.json` — rate-card fields (`usd_per_1m_*`, `flat_usd_per_month`,
  `_rate_card` source) on metered/prepaid-quota seats.
- `lib/fleet_usd.py` (new) — rate-card load + per-session USD computation + 24h
  aggregation; per-file mtime cache so the 5-min exporter tick does not re-parse
  every session jsonl each run.
- `bin/pi-issue-run` — at run end records the session's USD into the prepaid-usage
  counter (UNAVAILABLE for no-rate-card seats).
- `lib/seat-lib.sh` — `_record_prepaid_usd` / `_session_usd_from_usage`;
  `remote_agent` seats record `UNAVAILABLE:remote`.
- `libexec/fleet-metrics-export.py` — `_emit_usd_24h` emits `fleet_usd_24h`
  (metered/flat_share) + `fleet_usd_per_merged_pr` on the existing 5-min tick.
- `measure.sh` (new) — interactive snapshot; `bash measure.sh | grep -E '^usd_24h:'`.
- `prompts/weekly-fleet-review.md` — $/merged-PR seat table + worst-seat read.
- `tests/fleet-usd-spend.test.sh` (new) — locks the rate-card source/date, the
  usd_24h line, the shared math, the exporter's fleet_usd_24h family, the mtime
  cache, and the UNAVAILABLE (never-fabricated-$0) contract.
- `MANIFEST` — deploy `lib/fleet_usd.py` + `measure.sh`.

Not-a-build: no new timers, no new systemd units. measure.sh is a reporting helper
(not a fleet organ, not on the heartbeat registry).
