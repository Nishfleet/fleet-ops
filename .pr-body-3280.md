Raise fleet-work.slice TasksMax from 3000 to 8000 and the spawn-guard pair to 8000/7500.

Idle pi is 105-140 MB / 11 threads (measured 2026-09-04 07:50Z). 25 workers each running 1 implementer + 8 scouts is 25 * 9 * 11 = 2475 tasks from pi threads alone, plus bash/git/test children. The old 3000 would clip that manager-loop shape. 8000 is ~3x the 2475 pi-thread floor and still ~3x below the 24,945 runaway that motivated the fence.

RAM remains admission. MemAvailable and ram_gb_per_worker (still 0.5) decide how many workers start. Raising TasksMax is not a licence to admit more work. spawn-guard-core fails loud at 7500 before systemd's silent kill.

The drop-in already existed live only. This PR repo-izes it and the spawn-guard constants (same pattern as #3263 for the provider extensions) so install.sh cannot drift them apart.
