Closes #5890

## Fault

`bin/lifecycle-label-sweep` re-posted the identical `spec-gate: refused agent-ready` comment on every hourly tick for a spec-gate-refused issue whose body never changes (#4939: 45 identical nishfleet-worker comments over ~45h, measured 2026-09-12 08:50Z). The refusal had no memory, and the escalate-senior bodies it kept refusing were themselves spec-less (filed without the four #543 spec lines), so the loop never drained — the retry-forever half fed the re-refuse-forever half.

## Fix (both prongs of #5890)

1. **Comment once per body digest** (`bin/lifecycle-label-sweep`): the sweep now persists `REFUSAL[<repo>#<num>] = sha256(body)` of the last refused comment in the summary state file it already owns (`LIFECYCLE_SWEEP_SUMMARY`, `refusals` key), seeded at startup and written back after every sweep. While the digest is unchanged it logs one terse `unchanged body digest — comment skipped` line and posts nothing; an edited body yields a fresh digest and is re-evaluated next tick. The digest is recorded only after the comment actually lands, so a dropped notice (fleet-ops#5439) retries instead of vanishing. No new state file, no new unit — the mechanism rides the sweep's existing summary.
2. **Escalation filers emit the four spec lines**: `bin/pi-escalation-audit-tally` (the admitted fix issue) and `.github/scripts/ci-failure-escalation-detector.mjs` (`renderIssueBody`, the escalation itself) now derive `termination: / accept: / required: / metric:` from the failing check name and repo, plus the #3255 `moves: product_merges_per_day` line — so every escalation admission is spec-gate-admissible on the FIRST sweep instead of entering the storm.

## metric (acceptance bullet)

Measured 2026-09-13 17:09Z, trailing 24h, `repo:Nishfleet/fleet-ops` issues carrying the `spec-gate: refused agent-ready` marker: 163 issue-updates across 100+ distinct issues (`search/issues`, `updated:>=2026-09-12T17:09Z`; 100 = the distinct-issues floor, the API caps `items` at 100 per page). After merge the 24h comment count is structurally <= the number of distinct refused issues: the sweep comments at most once per distinct body, enforced by `tests/lifecycle-label-sweep-refusal-dedup.test.sh` (run 4: unchanged body → no third comment).
