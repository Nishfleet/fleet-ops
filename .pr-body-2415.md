## What was wrong

Heartbeat 2026-08-30T17:30Z: opencode/muse-spark-1.2-contributor-free was
seat_dead=true, health_class=corpse, 150 consecutive 500s — yet still read
as "still on a 24h retry cycle". The corpse threshold (>=25 consecutive
failures -> seat_dead=true + terminal "corpse" class, fleet-ops#2145/#2327)
already existed, but the corpse ledger entry KEPT `usable_at` at the 24h
quarantine cap written by computeUsableAt, so every reader (heartbeat
included) saw a corpse with a comeback clock — a corpse scheduled for
re-probe forever while consuming probe budget.

The mechanical fix the issue asked for (a failure-count threshold that
promotes transient_http to permanent retirement) exists; the **permanent**
half was missing: a corpse still carried a retry clock.

## Fix

Out-of-repo live extension at ~/.pi/agent/extensions/seat-health.ts
(allowlisted, closure-tested from this repo like #1466/#1422/#2145):

- `writeSeatLedgerEntry`: the moment `shouldMarkSeatDead` fires the corpse
  now gets `usable_at = null` — a corpse is retired, it carries NO comeback
  clock. The 1422 quarantine wall is for WALLED seats that may recover,
  never a retry schedule for a corpse. Recovery is manual-only since the
  seat-walled-probe weekly probe organ was deleted (fleet-ops#2394).
- A further failure write on the corpse keeps the clock null (no reader can
  resurrect a retry cycle — D14).
- Routing is unchanged: seat_usable / pick_seat exclude seat_dead=true
  before any usable_at check, so the cleared clock changes nothing for the
  router.

In-repo (this PR):

- `tests/seat-health-seat-dead.test.sh`: D10 now asserts the corpse
  record's usable_at is null (was: 24h cap 86400 — the stale contract that
  failed the VPS closure check, fleet-ops#2422) and adds D14 — a 26th
  failure keeps seat_dead=true / class corpse / usable_at null; D11
  (healthy write recovers) and D12 (below-threshold quarantine wall
  unchanged at c=24, 57600s step) still hold.
- `config/seat-caps.json` `_comment_seat_dead` documents the #2415
  contract (corpse = no comeback clock).
- Live corpse ledgers backfilled to `usable_at: null` with `.bak` copies
  (opencode__muse-spark-1.2-contributor-free, devin__glm-5-2), so the
  heartbeat reads them as retired immediately, not after the next deploy.

Mechanism (fleet-ops#366): the closure test `tests/seat-health-seat-dead.test.sh`
is the regression gate — it now asserts the no-usable_at-comeback-clock
corpse contract (D10/D14), so any future writer that re-anchors a corpse's
24h wall fails the VPS closure check instead of silently re-alarming the
heartbeat. The threshold promotion itself (>=25 -> corpse) is the
seat_dead_consecutive_threshold config gate from #2145/#2195, unchanged.

Related findings filed separately (out of scope, not fixed here):
fleet-ops#2419 (unjustified-wait exempts the corpse class) and fleet-ops#2420
(surface transient corpses for manual repair).
