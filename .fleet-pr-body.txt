## What / why

comeback-release (`bin/fleet-seat-comeback-release`) skipped **every** seat
key absent from the `providers.<p>.models` map as a "phantom" (fleet-ops#3661).
That blanket guard over-rejected REAL provider seats whose caps row is merely
missing — cap=0 parked for re-audition, a provider config out of date — so an
expired `usable_at` left them stuck overdue forever (lived finding: orcarouter/
orcarouter/free 6h+ past usable_at, never re-auditioned; seats_healthy sat at
9/41 and FleetSloSeatAvailSlowBurn stayed lit). Meanwhile TRUE probe-artifact
phantoms (model id a unit-output filename fragment, devin/glm-5-2-.out) were
skipped but never retired, so the census and the thorough heartbeat detector
kept counting them comeback-overdue.

## Fix

Split the phantom branch so an expired usable_at deterministically returns or
re-probes each seat:

1. A **probe-artifact** key (model id ends in `.out`/`.err`/`.log` — the
   #3661/#4018 shape) is a true phantom and is now **retired out of the live
   roster** (terminal move to a dated `seats-phantom-retired-<ts>/` dir,
   mirroring the corpse retirement #2716). It can never be unwalled, so
   leaving the ledger in `lanes/seats/` made every detector read it overdue
   forever.
2. Any **other** key the caps check rejects is a REAL routable seat (its caps
   row is just missing). It now falls through to the normal wall-clock path
   and is **re-probed when its wall expires** — the automated re-audition
   (a success unwalls it; a 402/429 re-benches it into a future wall).
3. The expired / interval-breach recounts exclude only probe-artifact
   phantoms, so a real-but-unconfigured seat that ends the sweep still past
   usable_at by >1 probe interval is correctly a releaser miss.

New helper `_seat_is_probe_artifact` distinguishes the two; `retire_phantom_ledger`
retires a phantom (held while its meaningless wall clock is still in the future).
