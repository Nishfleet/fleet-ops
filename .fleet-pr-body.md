## fix(debug-playbook): edit no-ops are not failed debug attempts (fleet-ops#4946)

### Problem
The debug-playbook gate counted every `isError` toolResult toward the
two-attempt threshold that flags a session as a multi-attempt debug that
ended without a playbook note (`DEBUG-PLAYBOOK-GATE-BLOCK` / `-MISSING`).

An `edit` tool no-op reply — "No changes made to <path>. The replacement
produced identical content" — is **not** a ran-and-failed command. It is the
edit-tool analog of a grep/rg/diff/ls no-match: the tool completed and the
file is already in the requested state.

The live fleet-ops#4946 alarm is a concrete false positive. A normal 0509
pricing-implementation session surfaced with two counted attempts:

1. an `edit` no-op on `tests/pricing.route.test.ts` ("replacement produced
   identical content") — benign, not a debug attempt
2. a stray `gh` JSON-field typo on a `pr view` probe

The edit no-op is what the alarm snippet names directly. Exempting it drops
the session to a single real failure — below the two-attempt threshold — so
the gate stops flagging routine implementation work.

### Fix
`lib/debug-playbook.py` gains an `EDIT_NOOP_RE` exemption in `result_failed`,
alongside the existing `SPAWN_BLOCKED` (fleet-ops#4620) and schema-validation
(fleet-ops#2210) exemptions. A matching toolResult is treated as a clean
attempt, exactly like the no-match probes already exempted.

**Scoped deliberately:** this only changes the debug-playbook gate.
`lib/failed-command-flagged.py` is **untouched** — there the same string
remains a real swallowed failure the worker must flag in user-facing text
(fleet-ops#1139). The two detectors measure different things: the playbook
gate is about *debugging sessions needing a note*; the failed-command flag
is about *user-facing honesty about a swallowed failure*.

### Verification
Real run against the exact session that filed fleet-ops#4946, using the
edited helper:

```
$ python3 lib/debug-playbook.py gate --path \
    /home/nish/.pi/agent/sessions/pi-issue-0509-2315/\
2026-09-10T12-26-47-060Z_0509-2315-1789043206271645694.jsonl
DEBUG-PLAYBOOK-GATE-OK: no missing playbook        # was: GATE-BLOCK rc=1
```

The session now yields a single failure (the gh JSON-field typo) instead of
two — below the two-attempt threshold.

run-proof: tests/fleet-debug-playbook.test.sh (new 7g case + all prior
cases green), tests/pi-issue-run-debug-playbook-gate.test.sh,
tests/signal-reconcile.test.sh, tests/seat-lib.test.sh,
tests/fleet-failed-command-edit-unmatch.test.sh (confirms #1139 flag path
unaffected); bin/sgscan clean.

net-positive-because: 36 added lines = a named exemption regex with a
scoped justification comment in the gate plus one regression test block for
that exemption; no new machinery, no net-positive surface — the added lines
pay back the false-alarm 4946 debt by preventing repeated gate-block alarms
on routine edit work.
