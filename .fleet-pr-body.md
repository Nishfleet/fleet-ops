fix(signal-reconcile): retroactively downgrade already-open agent-ready DEGRADED-LANES issues to observe-to-close (Relates to #4987)

## Problem

#4981 routes DEGRADED-LANES alarms to `observe-to-close` — but only for
**new** filings at file time. An already-open `agent-ready` DEGRADED-LANES
issue (filed in the ~3 minutes before #4981 landed — #4987 itself was filed
14:56:12Z vs #4981 merged 14:59:17Z) is deduped and heartbeat-commented by the
reconciler but **never retroactively downgraded** to `observe-to-close`. The
intake therefore keeps claiming it and working it, burning an admission-priced
worker seat on an observe-to-close-only alarm that carries **no manual action**
(start/restart lanes release via StartLimitBurst/OnFailure, not a worker).

Shell evidence on the live box: `systemctl --user show pi-issue@0509-2507.service`
→ `inactive`/`dead` (the lane recovered on its own) — exactly the outcome a
fleet worker could not have produced, and the reconciler's own observe-to-close
closed #4987 on the green tick at 15:57:54Z. The wasted worker claim that this
issue triggering is the proof the retroactive downgrade is missing.

## Fix

In the reconciler's dedupe branch, when a live DEGRADED-LANES signal maps to an
already-open issue still carrying `agent-ready` / `agent-in-progress`, re-label
it to `observe-to-close` (removing those labels) so the intake stops claiming
it. Observe-to-close still closes it on the green tick regardless of label
(signal-reconcile test 14b already proves the label does not change the closeout
path). This is a pure observability/routing fix — exactly the #[366] mechanical
shape: a gate that prevents the wasted worker seat.
