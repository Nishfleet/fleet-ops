## Summary

The 0509-2144 worker checking PR #2232's merge-queue status ran

```
gh pr view 2232 -R Nishfleet/0509 --json mergeStateStatus,isInMergeQueue,mergeQueueEntry 2>&1 | python3 -c "import sys,json; d=json.load(sys.stdin); ..." 2>&1
```

The bogus merge-queue fields make `gh` print its field error to stderr and leave stdout empty; the trailing `python3` reads empty stdin and fails `json.load` with `JSONDecodeError: Expecting value: line 1 column 1 (char 0)`. Unlike the `| head` sibling (fleet-ops#1193), the `| python3` tail does NOT mask the failure: python exits 1, so the toolResult carries `isError=true` and `Command exited with code 1`. The worker walked it past with cause-prose naming the field ("the `isInMergeQueue` field doesn't exist") — a cause, never a flag (fleet-ops#1052) — then silently retried.

This is the piped-to-python variant of the `gh pr view --json <invalid-field>` class. It is distinct from the UNPIPED shape (#1244, prints `Unknown JSON field`) and OPPOSITE of the `| head` pipe-mask (#1193, isError=false, stays silent): here the exit stays non-zero and the failure is real. The detector already catches it via the generic isError path. This PR locks the class with a regression test (mechanical-fix, fleet-ops#366) and tightens the worker-prompt + lib-docstring guidance so the recurring seat-burn shape is documented alongside #1244/#1193.

Scope: detector test + prompt/docstring citations only. No detector logic change, no new machinery, no unit/timer/workflow.
