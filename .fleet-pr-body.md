## What

`DEGRADED-LANES` alarm issues are observe-to-close-only: the heartbeat Tier 1 §7 sees auto-restart lanes as "held, no work — StartLimitBurst / OnFailure are the right release path", so there is no manual action a fleet worker can take. Despite that, the detector→queue reconciler routed every one of them to `agent-ready`, so the intake claimed them and burned an admission-priced worker seat per occurrence for nothing.

The regression is directly visible in #4966's own siblings: #4668, #4701, #4931 and #4947 each carried `agent-ready`, each got claimed by a worker, and each was closed by the reconciler's plain observe-to-close with zero worker code. This PR teaches the reconciler to file `DEGRADED-LANES` under `observe-to-close` (fleet-ops#1401) so the intake does not claim them — the detector's own observe-to-close still closes them on the green tick (covered by the new test).

## Change

- `lib/detector-queue-reconciler.py` — `routing_labels()`: `DEGRADED-LANES` now routes to `observe-to-close`, not `agent-ready`.
- `tests/signal-reconcile.test.sh` — scenario 14: (a) a fresh `DEGRADED-LANES` alarm files under `observe-to-close` and explicitly not `agent-ready`; (b) the observe-to-close closeout still fires once the lanes go green.
