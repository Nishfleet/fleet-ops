## Summary

The thorough heartbeat reported `worktree_dirs=316` with no reaper result in the snapshot. The reaper (`bin/fleet-worktree-reaper`) already writes a daily summary JSON (`post_count`, `reaped`, `skipped_*` breakdown, `ts`) and already reports per-worktree age/owner and reaps only provably-finished cycles — but the current heartbeat exporter (`libexec/fleet-metrics-export.py`) never surfaced that summary as a metric. The gauge the retired opus-heartbeat added was retired with it (fleet-ops#4141), so the count is again invisible to the heartbeat.

This change makes the existing reaper summary observable to the current heartbeat exporter:

- **`libexec/fleet-metrics-export.py`** reads the reaper's last-run summary and emits a worktree gauge family into `fleet.prom`:
  - `fleet_worktree_dirs` = `post_count` — the count metric the heartbeat gauges for unbounded worktree sprawl.
  - `fleet_worktree_reaped` = how many the reaper removed that run.
  - `fleet_worktree_reaper_heartbeat_seconds` = run timestamp (freshness).
  - `fleet_worktree_reaper_present` = always emitted; 0 when the summary is missing/unparseable/stale so the heartbeat can tell a dead reaper from a healthy one. Count gauges are omitted when the summary is absent — a missing reaper result means the count is unknown, not 0.

- **`tests/fleet-metrics-export.test.sh`** pins the new family: present-summary parse, missing/unparseable/stale degradation, and `main()` emission (present always, count+reaped+heartbeat only when fresh). The existing `main()` tests now point `WORKTREE_REAPER_SUMMARY` at a nonexistent path so they stay hermetic.

No new mechanism: the reaper timer, the heartbeat exporter timer, and the existing summary-file path are all reused. The reaper's safety gates (live-worker, dirty, not-pushed, not-terminal, age, fail-closed) are untouched — only observability is added.
