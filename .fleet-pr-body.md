## fix(signal-reconcile): stop queueing the DEBUG-PLAYBOOK-GATE-BLOCK alarm (fleet-ops#4946)

### Problem
`DEBUG-PLAYBOOK-GATE-BLOCK` keys on the RULE, not the session (fleet-ops#4516/4579): the session token is stripped as a dynamic token, so every in-window session-close gate failure derives the identical `loud/debug-playbook-gate-block`. It can only go green on a tick whose 24h window holds ZERO gate-block lines fleet-wide, so observe-to-close never fires while the fleet keeps debugging — the alarm goes stale-red and re-claims its work unit into StartLimitBurst churn.

#4953 fixed the root cause of THIS session (an edit no-op is not a failed attempt, so 0509-2315 now re-gates OK), but #4946 could not observe-to-close because other sessions' gate-block lines kept the same rule key alive.

### Fix
Add `DEBUG-PLAYBOOK-GATE-BLOCK` to SKIP_TAGS in `lib/detector-queue-reconciler.py`, the same never-green rule-keyed shape the reconciler already skips for DEBUG-PLAYBOOK-MISSING (#4620), CLAIM-REAP-STARTED (#4918), CLAIM-RELEASED (#4930), PACKETS-ARCHIVED (#4930) and FAILED-COMMAND-FAIL (#4944). With the tag skipped, the already-open `loud/debug-playbook-gate-block` alarm (live #4946) observe-to-closes on the next tick while lines keep firing (9c-close terminus).

**Scoped deliberately:** the gate's enforcement is untouched — `bin/pi-issue-run` still exits 1 (WORK death) and fails the heartbeat tick while the debt is non-zero, and the same session is already carried per session by the detector's own `signal: debug-playbook/<slug>` + daily-aggregate filings (#4384). Only the redundant fleet-ops ISSUE carrier is dropped.
